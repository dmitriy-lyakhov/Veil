# Veil

VPN-протокол и приложение для Windows, macOS и Linux: ядро WireGuard (Noise IK) внутри HTTPS на порту 443.
Основной транспорт — HTTP/3 (QUIC, UDP/443) с HTTP-датаграммами, запасной —
HTTP/2 поверх TLS 1.3 с отпечатком Chrome (TCP/443). Для всех, кто не знает
секретного токена, сервер — обычный сайт по обоим протоколам.

Кроме собственного протокола приложение устанавливает на сервер и подключается по обычным
**WireGuard, AmneziaWG, OpenVPN и IPsec/IKEv2** (см. «Другие протоколы»).

## Как это устроено

```
                                     ┌→ HTTP/3 датаграммы (RFC 9297) → QUIC → UDP/443   основной
IP-пакеты → WireGuard (wireguard-go) ┤
                                     └→ кадры в HTTP/2 POST-потоке → TLS 1.3 → TCP/443  запасной
```

- **Отпечаток Chrome везде**: HTTP/2 идёт через uTLS (ClientHello Chrome 120), HTTP/3 — через uquic с QUIC-пресетом Chrome 115 плюс ECH GREASE (ALPS, compress_certificate, `max_datagram_frame_size`, без Go-маркеров); оба отпечатка согласованы между собой («Chrome около 120»). Постквантовый key share современного Chrome добавить нельзя: ClientHello перестаёт помещаться в один Initial-пакет, а uquic не умеет делить его на два. HTTP/3-слой клиента написан поверх uquic вручную (SETTINGS, QPACK-заголовки в порядке Chrome, HTTP-датаграммы). Тест `TestH3ClientLooksLikeChrome` разбирает реальный Initial-пакет.
- **HTTP/3**: запрос `POST /api/v2/<случайный путь>`, пакеты WireGuard идут ненадёжными HTTP-датаграммами — без проблемы TCP-over-TCP. Пакеты больше текущего лимита QUIC-датаграммы режутся на фрагменты; лимит узнаётся из ответов quic-go и растёт вместе с PMTU.
- **HTTP/2**: тот же запрос, тело в обе стороны — поток кадров `[тип][длина][данные]`.
- **Padding**: первые пакеты сессии в обоих транспортах дополняются случайным мусором; дальше каждая датаграмма получает случайный хвост 0–39 байт (WireGuard выравнивает пакеты до 16 байт, и без этого длины кучкуются на нескольких остатках).
- **Alt-Svc**: TCP-сайт объявляет `h3=":443"`, как обычные сайты, поэтому QUIC на этом адресе выглядит естественно.
- **Аутентификация**: `Authorization: Bearer` — HMAC-SHA256 от времени и nonce, окно ±90 с, повтор токена отклоняется. Без валидного токена — страница сайта, 404 в стиле nginx (включая заголовки `Server` и `Connection` и padding для Chrome, как у настоящего nginx).
- **Порт 80**: отвечает редиректом `301` на HTTPS (как `return 301 https://$host$request_uri` в nginx), чтобы закрытый порт не выдавал сервер.
- **Сертификат**: самоподписанный со случайным именем вида `abcdefg.com`, выпущен «задним числом» (20–120 дней назад), срок около года; клиент проверяет SHA-256 отпечаток публичного ключа (pinning). В TLS 1.3 сертификат зашифрован и наблюдателю не виден. Лучше всего задать домен: тогда сайт отдаётся с настоящим сертификатом Let's Encrypt.
- **Выбор транспорта**: Happy Eyeballs по четырём вариантам с шагом 250 мс — IPv6+HTTP/3 → IPv6+HTTP/2 → IPv4+HTTP/3 → IPv4+HTTP/2, побеждает первый успешный. Если UDP режут, клиент оказывается на HTTP/2 через ~250 мс и пробует вернуться на HTTP/3 при каждой плановой смене соединения. Профиль может ограничить транспорты: `"transports": ["h2"]`.
- **Устойчивость**: обрыв TCP не рвёт WireGuard-сессию, переподключение ~100 мс; каждые 5–15 минут соединение плавно меняется на новое.
- **Внутри туннеля** — dual-stack: IPv4 `10.66.0.0/24` и случайная ULA `/64` с NAT66, весь v4/v6 трафик идёт в туннель.

## Приложение

Графическое приложение на Fyne, тёмная тема, нижняя панель из четырёх вкладок:

- **Главная**: кольцо подключения, ссылка на раздельное туннелирование, карточка выбранного сервера (по нажатию — нижняя панель выбора сервера с радиокнопками и шестернёй управления).
- **Поделиться**: выдача и список клиентов выбранного сервера (вкладки «Подключение» и «Пользователи»).
- **Настройки**: Серверы, Подключение (DNS, раздельное туннелирование, KillSwitch), Приложение (автозапуск, автоподключение, запуск в трее, проверка обновлений, журналы, сброс), Резервная копия, О Veil, Закрыть приложение.
- **«+»**: вставка ключа `veil://`, файл с настройками (`.veil`, `.conf` WireGuard или AmneziaWG, `.ovpn`), установка на свой сервер по SSH, «ближайший вход».

Страница сервера открывается без запроса пароля: вкладка «Протокол» показывает сведения из профиля, а вход по SSH запрашивается только в момент действия, которому он нужен (сведения с сервера, настройки домена и пароля, каскад, управление). Сессия SSH сохраняется на время работы приложения. Вкладка «Управление»: проверить сервер, обновить пакеты, перезагрузить, удалить из приложения, удалить Veil с сервера.

Одновременно работает один экземпляр приложения: повторный запуск поднимает окно первого (в Windows — в том числе из трея).

## Раздельное туннелирование

Настройки → Подключение → «Раздельное туннелирование по сайтам» (или ссылка на главном экране):

- Два списка: **«Через VPN»** и **«Напрямую»**. Если «Через VPN» не пуст, в туннель идёт только он; иначе — весь трафик, кроме «Напрямую». «Напрямую» главнее.
- Записи по одной в строке: ссылка (URI) или домен, IPv4, IPv6, подсеть IPv4 или IPv6 (`https://example.com/x`, `203.0.113.5`, `2001:db8::/32`). Домены разрешаются в адреса при подключении и обновляются каждые 10 минут.
- Меню ⋮: добавить из каталога, добавить из файла, заменить из файла, сохранить в файл, очистить.
- **Каталог iplist.opencck.org**: сервисы по группам с поиском и кнопкой «Выбрать все». Файл большой (около 45 МБ, скачивается несколько минут), приложение разбирает его потоком и сворачивает адреса в подсети (около 1,4 млн записей превращаются примерно в 12 тысяч подсетей). Каталог сохраняется на устройстве.
- Маршруты добавляются через IP Helper API (Windows), пакетным вызовом `ip` (Linux) или по одному через `route` (macOS). Предел — 300 000 маршрутов и 4000 доменов за раз.
- Списки хранятся в `routing.json` и действуют для всех профилей; применяются при следующем подключении.

## KillSwitch

Мягкий KillSwitch (Настройки → Подключение → KillSwitch): пока туннель поднят, рядом с его маршрутами лежат запасные маршруты в никуда с большой метрикой. Пока туннель работает, побеждают его маршруты; если помощник аварийно завершился и адаптер исчез, остаются только запасные, и трафик блокируется, а не уходит в открытую сеть. При обычном отключении блокировки нет. Остатки после сбоя снимает кнопка «Снять блокировку интернета» (команда `veil unblock`) либо следующее подключение. Работает в Windows и Linux; в macOS у маршрутов нет метрик, поэтому не поддерживается.

## Другие протоколы

На странице сервера, вкладка «Протокол» → «Другие протоколы». Каждый протокол ставится по SSH отдельной службой, не затрагивающей чужие настройки; затем создаётся профиль, к которому можно подключиться из приложения, а конфигурацию — выдать другим клиентам (QR и файл).

| Протокол | На сервере | Подключение из приложения |
|---|---|---|
| WireGuard | интерфейс `veilwg`, `/etc/wireguard/veilwg.conf`, служба `wg-quick@veilwg`, подсеть по умолчанию `10.8.1.0/24`, порт UDP по выбору | wireguard-go в самом приложении |
| AmneziaWG | интерфейс `veilawg` (пакет `amneziawg` из PPA Amnezia, Ubuntu/Debian), параметры Jc, Jmin, Jmax, S1, S2 и др. | движок `amneziawg-go` |
| OpenVPN | PKI easy-rsa в `/etc/openvpn/veil`, служба `openvpn-server@veil`, UDP или TCP, подсеть по умолчанию `10.9.0.0/24` | установленный в системе `openvpn.exe` (в приложение не встроен) |
| IPsec/IKEv2 | strongSwan (swanctl), вход по логину и паролю (EAP) или сертификату, пул по умолчанию `10.9.0.0/24` | встроенный VPN Windows (`Add-VpnConnection`, `rasdial`); сертификат центра сертификации импортируется только после подтверждения |

Ограничения: WireGuard и AmneziaWG ставятся только для IPv4; установка рассчитана на Debian/Ubuntu и Fedora/RHEL (apt, dnf, yum). **Подсети OpenVPN и IPsec по умолчанию совпадают (`10.9.0.0/24`):** на одном сервере держите их с разными подсетями.

## Сайт-прикрытие и админ-панель

- При установке генерируется сайт-визитка выдуманной компании (ru или en): название, род деятельности, услуги, описание, город, часы работы, логотип, одна из 6 палитр и 3 вёрсток, случайный порядок секций. Форма заявки, `robots.txt`, favicon; всё прочее — 404 в стиле nginx. Телефонов и e-mail нет — чтобы случайно не указать чужие реальные контакты.
- **Админ-панель доступна только через VPN**: `https://10.66.0.1/admin` (адрес сервера в туннеле). Запросы к публичному адресу сервера (в том числе к `/admin`) при включённом VPN идут через туннель, поэтому сервер видит в них клиента VPN и открывает панель. Без VPN `/admin` неотличим от несуществующей страницы. Внутри — вход по логину и паролю (bcrypt, блокировка IP после 5 ошибок на 15 минут, cookie `HttpOnly; Secure; SameSite=Strict`, CSRF-заголовок).
- В панели: онлайн-статус клиентов, транспорт и адрес каждой сессии, последнее рукопожатие, трафик; добавление клиента (выдаётся ссылка `veil://` и файл `.veil` — один раз, в них приватный ключ) и удаление с немедленным разрывом сессий.
- Пароль админки генерируется при первой установке и показывается в журнале установки и в карточке сервера в приложении.

### Свой сайт-прикрытие из репозитория

Вместо сгенерированного сайта сервер может отдавать статический сайт из вашего репозитория (GitHub, GitLab, Gitea/Forgejo или любой https-адрес при наличии `git` на сервере): раздаётся только статика, обновление раз в 6 часов и по запросу, при сбое остаётся последняя удачная версия. Подробно, включая ограничения и меры безопасности: [docs/COVER-SITE.md](docs/COVER-SITE.md).

## Каскад произвольной длины

- Маршрут клиента: `вход → узел 2 → … → выход`, число узлов не ограничено (проверено на 15). WireGuard-сессия сквозная от клиента до выхода, промежуточные узлы пересылают зашифрованные пакеты и не видят трафик; MTU и шифрование не растут с числом узлов.
- Каждый узел знает только своих соседей: ключ каскада (`veil-relay://`) выдаёт следующий узел предыдущему. Регистрация клиента проходит по цепочке через скрытый API на секретном пути (без ключа — 404), каждый узел выдаёт предыдущему отдельный ключ для этого клиента. Удаление тоже идёт по цепочке.
- Маршрут собирается пошагово: админка/приложение спрашивает у узла, куда он может отправить дальше.
- В приложении: «Связать со своим сервером» или «Построить каскад из нескольких серверов» — приложение само выдаёт ключи и связывает соседей по SSH.

## Автомаршрут по задержкам

- Каждый узел раз в ~30 с (со случайным разбросом) замеряет задержку до соседей обычным HTTPS-запросом и сглаживает её.
- Входной узел собирает таблицу задержек у соседей (до недоступных напрямую — через соседей), узлы опознаются по публичному ключу.
- Вход и выход фиксированы; промежуточные узлы упорядочиваются точным перебором подмножеств (до 20 узлов) с ограничением «сколько промежуточных». На случайной сетке из 15 узлов жадный «ближайший сосед» даёт путь в среднем заметно длиннее оптимального (в тесте — на 63%).
- Перестройка: если другой путь быстрее на 20% и минимум на 5 мс два замера подряд, либо сразу, если узел текущего пути пропал. Конфиг клиента не меняется: на выходе несколько путей доступа ведут к одному WireGuard-пиру с теми же адресами.

## Ближайший вход

- Профиль может содержать несколько входов и явно заданный выход. Ключ клиента генерирует приложение; каждый вход регистрирует его с маршрутом (напрямую или автоматическим) до того же выхода.
- При каждом подключении и переподключении клиент параллельно замеряет TLS-рукопожатие до всех входов и идёт через самый быстрый; недоступный вход пропускается.
- Кнопка «Перепроверить ближайший вход» показывает задержки, записывает ближайший вход в профиль и, если туннель поднят, сразу переключает его.

## Управление клиентами

Раздел «Поделиться» (вкладка «Подключение»: имя пользователя, сервер, «Поделиться»; вкладка «Пользователи»: список с поиском). Создание (с маршрутом через каскад), переименование и заметка, блокировка/разблокировка (мгновенно: заблокированный клиент не проходит аутентификацию транспорта), «новый конфиг» (перевыпуск ключей), удаление. Конфиг передаётся QR-кодом, файлом `.veil` или ссылкой `veil://`.

Приложение управляет своими серверами по SSH через локальный сокет `/run/veil/ctl.sock` (`veil-server ctl …`); веб-админка — только изнутри VPN. Для списка пользователей и выдачи клиента нужен вход по SSH: пароль запрашивается один раз при первом обращении.

## Домен

Для каждого узла можно задать домен: сайт-прикрытие открывается по нему, сертификат Let's Encrypt выпускается автоматически (TLS-ALPN-01 на 443, порт 80 для этого не нужен). Новые клиенты и ключи каскада такого узла подключаются по домену с обычной проверкой сертификата; старые конфиги продолжают работать по IP с закреплённым сертификатом.

## Маскировка под чужой сайт

Режим для сетей, где фильтруют по имени сайта в TLS (SNI). Клиент шлёт настоящий ClientHello браузера с SNI популярного сайта (`ya.ru`, `yandex.ru`, `vk.com`, `mail.ru` или свой домен), а в поле `session_id` кладёт метку HMAC от общего ключа сервера и случайного числа из того же ClientHello. Сервер читает ClientHello **до** TLS-рукопожатия:

- метка верна — соединение идёт в туннельный TLS-сервер;
- метки нет или она неверна (браузер, сканер, активный проверяющий) — соединение прозрачно проксируется на настоящий сайт, и проверяющий видит его подлинный сертификат и ответы;
- повтор той же метки отвергается (окно 5 минут), расхождение часов клиента и сервера допустимо ±1 минута.

Включение: при установке сервера в приложении (поле «Маскировка под»), в приложении на странице сервера (вкладка «Протокол»), в админ-панели (блок «Сервер»), в консоли `veil deploy -front ya.ru`. Ключ создаётся при первом включении и не меняется при смене сайта; веб-панель его не показывает, приложение получает его по SSH и обновляет профиль владельца само.

Что меняется при включении:

- **Только TCP/HTTP/2.** QUIC нельзя прозрачно проксировать на чужой сайт, поэтому слушатель UDP/443 закрывается и открывается снова при выключении маскировки.
- **Конфиги, выданные раньше, перестают работать** (в них нет ключа): выпустите их заново. Клиент при такой ошибке подсказывает, что нужен новый конфиг. Ключи каскада, выданные этим сервером, тоже нужно выдать заново.
- **Домен и маскировка несовместимы по продлению сертификата:** проверка Let's Encrypt придёт без метки и уйдёт на чужой сайт. Выпущенный сертификат работает до окончания срока.
- **Панель `https://10.66.0.1/admin` работает как обычно:** соединения с адреса из подсети туннеля (его может иметь только аутентифицированный пир WireGuard) и локальные не проксируются. Решает адрес источника, а не назначения.
- Сервер должен сам доставать до выбранного сайта на 443: установщик проверяет это и предупреждает.

Ограничения. SNI-маскировка не помогает против проверки соответствия домена и адреса (сервер в Нидерландах с SNI `ya.ru` отличим от настоящих серверов Яндекса по IP и ASN) и против белых списков по адресам. Для таких сетей входной узел каскада ставят на адрес из белого списка (облако в России), а трафик дальше идёт по обычному каскаду; это описано, но в сети ТСПУ не проверялось.

## Пароль админки

Меняется в веб-панели (нужен текущий пароль) или в приложении по SSH; все сессии панели при смене завершаются.

## Способы добавить сервер

1. **Свой сервер по SSH**: IP (v6/v4), логин и пароль или SSH-ключ — приложение само ставит Veil и сайт-прикрытие.
2. **Ключ, файл или ссылка**: ссылка `veil://…` или `.veil`-файл из админ-панели; обычные `.conf` (WireGuard, AmneziaWG) и `.ovpn` тоже понимаются. В CLI: `veil import <файл|ссылка> [название]`.
3. **Дополнительные протоколы** на уже добавленном сервере — страница сервера → «Протокол».

## Резервная копия и данные

Настройки → Резервная копия сохраняет в один файл (`.veilbackup`, это zip) профили серверов, списки адресов и настройки. **В копии пароли и приватные ключи** — храните её в надёжном месте. Данные приложения лежат в каталоге конфигурации пользователя, в подкаталоге `Veil` (в Windows — `%APPDATA%\Veil`): `profiles`, `routing.json`, `settings.json`, кэш каталога и подкаталог `run` с журналами (`tunnel.log`, `app.log`). Журнал приложения пишется только когда включён в настройках и отключается сам через 14 дней.

## Сборка

Нужны Go 1.27+; для графического приложения ещё компилятор C (cgo): в Windows — MinGW-w64 (например, WinLibs), в macOS — Xcode.

```
# Windows (gcc из MinGW-w64 должен быть в PATH)
.\build-windows.ps1  # dist\windows\: veil.exe (GUI), veil-cli.exe и server\ с бинарниками для Linux
make windows         # то же через make, если он установлен

make macos-release  # обе сборки для macOS: DMG и портативная (универсальные: Intel + Apple Silicon, macOS 13+)
make dmg            # dist/Veil-<версия>.dmg: образ с установкой перетаскиванием в «Программы»
make portable       # dist/Veil-<версия>-portable.zip: Veil.app без установки, запускается из любой папки
make macos-app      # только dist/Veil.app с серверными бинарниками внутри
make server app     # dist/server/veil-server-linux-{amd64,arm64}, dist/veil
go build ./cmd/veil-cli   # консольный клиент без GUI (Linux-серверы, роутеры)
make test
```

`wintun.dll` (подписанная библиотека Wintun 0.14.1) встроена в `veil.exe` и при необходимости кладётся рядом с ним; папку `server` держите рядом с `veil.exe`: оттуда приложение берёт серверные бинарники для установки и обновления. Готовые сборки — на странице [Releases](https://github.com/dmitriy-lyakhov/Veil/releases).

## Использование

GUI: «+» → «Свой сервер по SSH» → IPv6 / IPv4, пользователь SSH, пароль или ключ → «Установить и подключить».
Приложение по SSH ставит `veil-server` как systemd-службу, открывает 80 и 443 в ufw/firewalld,
сохраняет профиль и поднимает туннель (в Windows запросит подтверждение UAC, в macOS — пароль администратора).
Повторная установка на тот же сервер добавляет новое устройство, не ломая старые.

CLI:
```
veil deploy -name ams -ipv6 2001:db8::10 -ipv4 203.0.113.10 -user root -password
sudo veil connect ams     # в Windows — из терминала с правами администратора
veil unblock              # снять остатки блокировки KillSwitch
```

## Статус платформ

| Платформа | GUI | Системный туннель |
|---|---|---|
| Windows | есть (`veil.exe`) | есть: Wintun (встроен), маршруты через IP Helper API, DNS через `netsh`, UAC; KillSwitch |
| macOS | есть | есть (utun, маршруты, DNS через networksetup); KillSwitch не поддерживается |
| Linux | есть | есть (TUN, ip route, resolvectl); KillSwitch |
| Android / iOS | Fyne поддерживает | нет (нужны VpnService / NetworkExtension) |

## Что не проверено

Версия 0.5.x собрана и покрыта тестами, но на момент выпуска **не проверялись на живых серверах и в Windows с правами администратора**: установка WireGuard, AmneziaWG, OpenVPN и IPsec, подключение по ним, системный туннель, маршруты списков, KillSwitch, автозапуск и трей. Консольные клиенты для Linux и macOS собраны, но не запускались; графическое приложение для них из Windows собрать нельзя. Сообщения об ошибках — в [Issues](https://github.com/dmitriy-lyakhov/Veil/issues).
