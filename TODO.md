# Что осталось доделать

Состояние на 2026-11-04. Приложение собирается, `go vet` и `go test ./...` проходят.
Ничего из перечисленного ниже не проверялось на живом сервере и в сети ТСПУ.

## 1. Маскировка трафика под чужой сайт (этапы 1 и 2 — код есть, не подключён к интерфейсу)

Сделано: пакет `internal/front` (разбор ClientHello, метка HMAC в `session_id`, прозрачное проксирование
посторонних на настоящий сайт, защита от повтора), поля `front_sni` / `front_key` в профиле, ссылках и входах каскада,
клиент (`client/dial.go`: SNI и метка, только TCP/h2), сервер (`server/front.go`, слушатель в `cmd/veil-server`,
API `settings/front`, выдача конфигов с ключом).

Осталось:
- [ ] Интерфейс приложения: поле «Маскировка под» (список ya.ru, yandex.ru, vk.com, mail.ru и свой домен) в форме установки
      сервера и в настройках сервера; вызов API `settings/front`.
- [ ] Интерфейс админ-панели (`internal/server/panel.go`): включение/выключение маскировки, предупреждение,
      что конфиги, выданные до включения, нужно выпустить заново (в них нет ключа).
- [ ] Показ в приложении, под что замаскирован сервер, и предупреждение при подключении старым конфигом.
- [ ] Сквозной тест «клиент + сервер + заглушка вместо чужого сайта» (сейчас есть только модульные тесты `internal/front`).
- [ ] UDP/HTTP/3: при включённой маскировке слушатель QUIC всё равно работает и отвечает нашим сертификатом.
      Либо отключать его при включении маскировки, либо проксировать QUIC (сложно).
- [ ] Проверить, что панель по адресу VPN (`https://10.66.0.1/admin`) открывается при включённой маскировке
      (обход `FrontBypass` по адресу туннеля).
- [ ] Этап 3 из плана: входной узел каскада на адресе из «белых списков» (облако в РФ). Описать в README, проверить каскад.
- [ ] Пробник для проверки в сети внутри РФ (на основе `tools/pcapcheck`): что видит DPI и активный проверяющий.
- [ ] README: раздел про маскировку и ограничения (SNI-маскировка не помогает против проверки соответствия домена и IP/ASN).

- [ ] Страницы входа и 404 проверить на отсутствие отпечатка Veil.

## 3. Приложение: сверка с дизайном десктопа

Сверено по замерам DOM: главная (широкая и узкая), настройки, подключение, KillSwitch, «Приложение», DNS,
«Доступ», «Новый сервер», список серверов, сведения о сервере, «О Veil», резервная копия, журналы.

Не сверено:
- [ ] Каталог адресов, раздельный доступ по сайтам, **страницы «Раздельный доступ: приложения» нет вообще**.
- [ ] Менеджер сервера (вкладки «Протокол / Сервисы / Каскад / Управление»), проверка входов, каскад, вход по SSH.
- [ ] Установка протоколов (AmneziaWG, WireGuard, OpenVPN, IPsec), сертификат центра, настройки подключения.
- [ ] «Доступ → Пользователи», новый клиент, клиент, QR и ссылка.
- [ ] Узкая раскладка (нижняя панель) на всех страницах, светлая тема на всех страницах, английский язык.
- [ ] Шаг между строками вложенных страниц в дизайне 10 px, у нас 8 px.
- [ ] Заголовок окна у дизайна свой (кнопки Windows 11), у нас системный.
- [ ] Плитка «Задержка» на главной всегда «—»: клиент не отдаёт задержку.
- [ ] Страница «Язык» в дизайне — расширение; у нас тема и язык отдельными страницами.
- [ ] Анимации переходов (кольцо: рябь при подключении) в дизайне есть, у нас нет.

Как сверять: дизайн открывается локально — скопировать `*.dc.html` из артефакта в папку, положить рядом `support.js`
(это `artifact-type/dc-runtime.js` из артефакта), поднять любой статический сервер; для страниц десктопа можно сделать
копии `Main.dc.html` с атрибутом `start="<экран>"`. Снимки приложения: `tools/uishot.sh <имя> <страница> <ширинаxвысота> [тема] [язык]`
(сборка с тегом `uidemo`, переменные `VEIL_DEMO`, `VEIL_SIZE`, `VEIL_THEME`, `VEIL_LANG`).
