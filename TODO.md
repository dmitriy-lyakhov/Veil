Состояние на 2026-11-04. Приложение собирается, `go vet` и `go test ./...` проходят.
Ничего из перечисленного ниже не проверялось на живом сервере и в сети ТСПУ.

## 1. Маскировка трафика под чужой сайт (этапы 1 и 2 — работает и подключено к интерфейсам)

Сделано: пакет `internal/front` (разбор ClientHello, метка HMAC в `session_id`, прозрачное проксирование
посторонних на настоящий сайт, защита от повтора, проверка домена `NormalizeSNI`), поля `front_sni` / `front_key` в профиле,
ссылках и входах каскада, клиент (`client/dial.go`: SNI и метка, только TCP/h2), сервер (`server/front.go`, слушатель в
`cmd/veil-server`), API `settings/front` (по управляющему сокету возвращает ключ, по веб-панели — нет).
Интерфейсы: поле «Маскировка под» в форме установки и в менеджере сервера (приложение), блок в админ-панели,
флаг `veil deploy -front`; приложение показывает, под что замаскирован сервер, а клиент подсказывает про новый конфиг.
Проверено тестами (`internal/e2e/front_test.go`): ключ в выданных конфигах, посторонние (с любым SNI) получают
сертификат и страницу заглушки, старый конфиг отвергается, панель по адресу туннеля открывается.

Исправлено при проверке: раньше выданные конфиги и ключи каскада **не содержали** ключ маскировки (в прошлой версии
этого файла было записано обратное), а `FrontBypass` решал по адресу назначения, а не источника.

Осталось:
- [ ] Этап 3 из плана: входной узел каскада на адресе из «белых списков» (облако в РФ): проверить каскад вживую
      (в README описан, не проверялся).
- [ ] Пробник для проверки в сети внутри РФ (на основе `tools/pcapcheck`): что видит DPI и активный проверяющий.
- [ ] Маскировка не проверялась на живом сервере и в сети ТСПУ: только тесты с заглушкой вместо чужого сайта.
- [ ] Конфиги с несколькими входами (мастер «Через ближайший вход»): при включении маскировки на одном из входов
      его запись в профиле нужно обновить (сейчас — выпустить заново).
- [ ] Продление сертификата домена при включённой маскировке (проверка Let's Encrypt уходит на чужой сайт).

Как сверять: дизайн открывается локально — скопировать `*.dc.html` из артефакта в папку, положить рядом `support.js`
(это `artifact-type/dc-runtime.js` из артефакта), поднять любой статический сервер; для страниц десктопа можно сделать
копии `Main.dc.html` с атрибутом `start="<экран>"`. Снимки приложения: `tools/uishot.sh <имя> <страница> <ширинаxвысота> [тема] [язык]`
(сборка с тегом `uidemo`, переменные `VEIL_DEMO`, `VEIL_SIZE`, `VEIL_THEME`, `VEIL_LANG`).
