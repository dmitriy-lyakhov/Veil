# Роли клиентов, админка каскада, https://admin и сетевой интерфейс

## Роли клиентов

При выдаче доступа (приложение: «Доступ», админ-панель: «+ Клиент», API `POST /admin/api/clients`) выбирается уровень:

| Роль | Что можно |
|---|---|
| **Пользователь** (`user`, по умолчанию) | только пользоваться VPN. Админка для него недоступна: сервер отвечает как на несуществующую страницу |
| **Администратор** (`admin`) | открыть админку и настраивать сервер и каскад через клиент, без пароля: его личность — ключ туннеля |

Подробности:
- Клиенты, созданные до появления ролей (роль не задана), работают как раньше: админка по паролю.
- Админка по-прежнему видна только изнутри туннеля. Роль определяется по адресу клиента в туннеле.
- В профиль администратора попадает адрес админки (`https://<адрес сервера в туннеле>/admin`) — приложение показывает кнопку «Открыть в браузере». Пароль администратора сервера в профиль не кладётся.
- Ссылка `veil://` администратора тоже содержит этот адрес (у остальных клиентов он из ссылки удаляется): по нему Android-клиент управляет клиентами сервера во вкладке «Доступ». У ссылок, выданных раньше, адрес берётся как первый адрес подсети клиента (`x.y.z.1`).
- Роль можно выбрать и при выдаче каскада одним подключением («Доступ → Поделиться каскадом…»).
- Сменить роль существующему клиенту через интерфейс пока нельзя — только выдать доступ заново.

## Адрес https://admin

Пока клиент подключён, приложение (помощник туннеля, у которого есть права) прописывает в файл `hosts` имя `admin` на адрес админки сервера и убирает запись при отключении (и при следующем запуске, если прошлый сеанс завершился аварийно). Тогда админка открывается по `https://admin`; сервер перенаправляет `/` на `/admin`. Если прав на запись в `hosts` нет, остаётся адрес по IP из профиля.

Ограничения:
- Браузер предупредит о самоподписанном сертификате — это ожидаемо.
- Имя `admin` прописывается только на компьютере с приложением Veil. На телефоне и в других клиентах пользуйтесь адресом по IP из профиля.
- В адресной строке браузера набирайте `https://admin` целиком, иначе одно слово воспринимается как поисковый запрос.

## Администрирование всего каскада сразу

Панель на входном узле управляет и следующими узлами каскада:
- вверху появляется выбор узла («Этот сервер» и все узлы дальше по цепочке); все действия (клиенты, ключи, каскад, настройки) выполняются на выбранном узле;
- запросы идут по тому же защищённому каналу, что и сам каскад;
- узлу разрешено администрировать сервер, только если ключ каскада выдан с флагом «администрирование» (`POST /admin/api/relays {"name": "...", "admin": true}`). Без флага ключ остаётся таким, каким был: он позволяет лишь отправлять клиентов через сервер.

Безопасность: ключ с флагом «администрирование» даёт узлу полный доступ к API админки сервера. Выдавайте такие ключи только своим узлам.

API: `POST /admin/api/cascade/nodes` — список узлов; любой запрос админки с `?node=A>B` выполняется на узле B, до которого запрос дойдёт через A.

## Сетевой интерфейс клиента

«Настройки → Подключение → Сетевой интерфейс» выбирает интерфейс, через который идёт весь трафик Veil до сервера (например, только VLAN 200). Применяется при следующем подключении.

- **Windows** — полностью: сокеты привязываются к выбранному интерфейсу, маршруты в обход туннеля берутся с его шлюза.
- **Linux, macOS** — сокеты привязываются к интерфейсу (`SO_BINDTODEVICE`, `IP_BOUND_IF`); у интерфейса должен быть маршрут до сервера.
- Если выбранного интерфейса нет или он не активен, подключение не начнётся и покажет понятную ошибку; «Автоматически» возвращает прежнее поведение.
- Сервер слушает адрес из `listen` в своём конфиге; чтобы он принимал клиентов только на одном адресе, укажите его там (`"listen": "10.0.200.5:443"`).
